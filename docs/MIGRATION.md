# DDL Migration

`yongol generate` diffs `specs/db/*.sql` against a baseline snapshot and emits `artifacts/db/migrations/NNNN_<desc>.sql`. The **DDL is always the SSOT** — migration files are derived artifacts.

## Layout

| Item | Path |
|---|---|
| DDL SSOT (user-edited) | `specs/db/<table>.sql` |
| Snapshot baseline | `specs/db/.generated_schema.sql` (managed by yongol) |
| Migration artifacts | `artifacts/db/migrations/NNNN_<snake_case_desc>.sql` |
| Apply tool | `golang-migrate` / `flyway` (user choice) |

## Flow

```
yongol generate <specs-dir> <artifacts-dir>
  - Validate (incl. MIG-001~006)
  - Migration emit
      - No snapshot   -> initial -> 0001_initial.sql
      - Snapshot + diff -> NNNN_<desc>.sql
      - No changes   -> skip
      - Refresh snapshot (with hash header)
  - Backend codegen
  - Frontend codegen
```

## DDL Comment Hints

Ambiguities the diff cannot resolve are declared via DDL comments.

| Hint | Location | Purpose |
|---|---|---|
| `-- @rename from=<old> [to=<new>]` | above `CREATE TABLE` / on column line | Emit `ALTER TABLE RENAME` instead of drop+add |
| `-- @cast using=<expr>` | column line | `USING <expr>` on type change |
| `-- @backfill default=<value>` | column line | Value to fill existing rows when adding NOT NULL |
| `-- @data_migration file=<path>` | above `CREATE TABLE` | Inject sidecar SQL |
| `-- @allow_destructive` | above `CREATE TABLE` | Suppress DROP warning (intentional) |

## Scenarios

### 1. New Project

```bash
yongol generate specs arts
# -> arts/db/migrations/0001_initial.sql
# -> specs/db/.generated_schema.sql
```

Apply: `migrate -path arts/db/migrations -database $DB up`.

### 2. Add a NOT NULL Column

Bare `email_verified BOOLEAN NOT NULL` -> MIG-002 ERROR. Two fixes:

```sql
-- (A) with DEFAULT
email_verified BOOLEAN NOT NULL DEFAULT false

-- (B) with backfill hint
-- @backfill default=false
email_verified BOOLEAN NOT NULL
```

Option (B) prepends `UPDATE users SET email_verified = false WHERE email_verified IS NULL;`.

### 3. Rename a Column

Without a hint, diff produces drop+add (data loss). Use `@rename`:

```sql
CREATE TABLE users (
    ...
    -- @rename from=email
    email_address VARCHAR(255) NOT NULL
);
```

Emits `ALTER TABLE users RENAME COLUMN email TO email_address;`. MIG-001 ERROR if `from` is not in the snapshot.

### 4. Intentional DROP TABLE

```sql
-- @allow_destructive
-- (remove CREATE TABLE from the file)
```

Without `@allow_destructive`, MIG-004 WARNING fires (`yongol generate` refuses on any WARNING).

## Migration File Format

```sql
-- Generated by yongol v0.1.22 at 2026-04-22T15:30:00Z
-- Changes:
--   * add column users.email_verified

BEGIN;
ALTER TABLE users ADD COLUMN email_verified BOOLEAN NOT NULL DEFAULT FALSE;
COMMIT;
```

Transaction-wrapped to prevent partial failure.

## Snapshot File

```sql
-- YONGOL_SCHEMA_HASH: 3a7f9c...
-- Generated by yongol v0.1.22 at 2026-04-22T15:30:00Z

CREATE TABLE users ( ... );
```

`YONGOL_SCHEMA_HASH` = sha256 of the body. Manual edits trigger hash mismatch -> MIG-006 ERROR.

## FAQ

- **Edit the snapshot?** No. Edit `specs/db/*.sql` and re-run generate.
- **Number collisions on merges?** `.generated_schema.sql` conflicts first. Resolve the git merge, re-run generate.
- **Rollback?** v1 is UP-only; DOWN is scheduled for v2.
- **MySQL / SQLite?** v1 is PostgreSQL-only.
