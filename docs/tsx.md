# TSX — React Frontend Declarations

The frontend SSOT. The `.tsx` source **is** the UI contract — yongol parses it with swc and cross-validates against OpenAPI.

## Location

```
<project-root>/frontend/
├── pages/*.tsx        # Page components (SSOT)
├── components/*.tsx   # User-authored custom components
└── lib/**             # (Optional) user utilities
```

After generate, files are mirrored under `arts/frontend/src/` (`.tsx` `.ts` `.jsx` `.js` `.css` `.svg`).

## Conventions

| Principle | Rule |
|---|---|
| API calls | `apiClient.<operationId>()` only. Raw `fetch`/`axios` forbidden |
| Primitives | Use `<Button>`, `<Card>`, `<Input>`, `<Form>`, `<Modal>`, `<Table>`, `<Select>`, `<Checkbox>`, `<Badge>`, `<Tooltip>` from `@/components/ui/` |
| Class merging | `cn()` from `@/lib/utils`. Direct `clsx` / `classnames` import forbidden |
| Types | Reference `@/types/api` (generated by openapi-typescript) |
| Design tokens | Semantic Tailwind tokens (`primary`, `destructive`, `accent`) — no hard-coded colors |

## Example

```tsx
import { useQuery, useMutation } from '@tanstack/react-query'
import { useForm } from 'react-hook-form'
import { apiClient } from '@/lib/api'
import { Button, Card, Input, Form } from '@/components/ui'

export default function WorkflowsPage() {
  const { data } = useQuery(['listWorkflows'], apiClient.listWorkflows)
  const create = useMutation({ mutationFn: apiClient.createWorkflow })
  const { register, handleSubmit } = useForm()

  return (
    <Form onSubmit={handleSubmit(v => create.mutate(v))}>
      <Input {...register('title', { required: true })} />
      <Input {...register('trigger_event', { required: true })} />
      <Button type="submit" variant="primary">Create</Button>
    </Form>
  )
}
```

## yongol-Owned Paths (Do Not Edit)

Regenerated on every `yongol generate`:

| Path | Content |
|---|---|
| `src/api.ts` | `apiClient` object keyed by operationId |
| `src/types/api.d.ts` | openapi-typescript output |
| `src/lib/utils.ts` | `cn()` |
| `src/components/ui/*` | 10 shadcn-like primitives |
| `tailwind.config.js`, `postcss.config.js`, `index.css` | Design tokens |
| `vite.config.ts`, `tsconfig.json`, `index.html`, `package.json` | Build config |

User-editable:
- Theme: `frontend.theme` in `manifest.yaml`
- Custom UI: add `specs/frontend/components/<Name>.tsx`
- Primitive overrides: pass `className` via `cn()` (trailing classes win)

## Cross-Validation Rules

| Rule ID | Level | Description |
|---|---|---|
| T-1 | WARNING | `@/components/` / `./components/` import target must exist |
| XOT-1 | ERROR | `apiClient.<op>()` must match an OpenAPI operationId |
| XOT-2 | ERROR | Path/query arg object keys must match OpenAPI parameter names |
| XOT-3 | WARNING | `useForm().register('x')` fields must exist in the OpenAPI request body schema |

**One-way**: TSX -> OpenAPI. An "OpenAPI endpoint unused by TSX" warning is not emitted — endpoints often have non-frontend consumers (mobile, CLI, partners).

## Parsing

yongol extracts ASTs with `swc` (`@swc/core`):

| AST pattern | Extracted |
|---|---|
| `apiClient.<op>(...)` CallExpression | `APICall.OperationID` |
| `queryFn: apiClient.<op>` / `mutationFn: apiClient.<op>` | `APICall` (TanStack Query) |
| `apiClient.<op>({ path: {...}, query: {...} })` | `APICall.Args` |
| `register('<name>', {...})` | `FormField.Name` |
| `import ... from '@/components/<Name>'` | `ComponentImport` |

`@swc/core` must be installed for `yongol validate` to parse TSX. Install it **at the project root** — the directory that contains `specs/` and (later) `arts/` — **never inside `specs/`**:

```bash
# From the directory that holds specs/
npm install --save-dev @swc/core
# Or point validate at an existing install:
export YONGOL_SWC_PROJECT_DIR=/path/to/any/node_modules/parent
```

yongol resolves `@swc/core` via standard Node parent traversal, so an install at the project root is picked up when validating `specs/frontend/pages/*.tsx`. Running `npm install` inside `specs/frontend/pages/` or `specs/frontend/components/` pollutes the SSOT tree with `node_modules/` and risks the TSX parser mistakenly scanning third-party `.tsx` / `.d.ts` files as user specs.

Without `@swc/core` reachable, validate fails fast with installation instructions.

## Implementation Notes

- `specs/frontend/pages/` and `specs/frontend/components/` are user-owned; mirrored to `arts/frontend/src/` on generate.
- `components/ui/` is yongol-owned — specs files at the same path are not copied (guarded by `isYongolManaged`).
- TypeScript validates field-level drift; yongol validates only the call contract.
